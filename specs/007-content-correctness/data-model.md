# Data Model: Content Correctness

## MineruReferenceV2

One strict Codex image-derived file per registered fixture:

- `schema_version`: exactly `2`
- `fixture_id`, archive SHA-256
- original PDF `{ relative_path, sha256, page_count }`
- main Markdown `{ relative_path, input_sha256 }`
- `printed_contents.state`: `present | absent`
- `printed_contents.regions[]`; exactly one `canonical: true` when present, none when absent
- `raw_heading_accounting[]`: every raw heading exactly once as `excluded | expected_body`
- `protected_ranges[]` and `expected_diagnostics[]`

Unknown/missing fields, duplicate identities, invalid hashes/ranges, v1 and unknown versions
are rejected.

## GroundTruthContentsRegion

- stable local `region_key`
- ordered PDF page indices
- Markdown exclusion start/end root-block anchors and hashes
- `canonical` boolean
- ordered logical entries

Regions are disjoint. Anchors bind raw root blocks rather than generated byte offsets.

## GroundTruthContentsEntry

- local entry key and title
- semantic kind: `part | chapter | section | appendix | frontmatter | backmatter | other`
- level 1-4 and optional printed page label
- optional body heading anchor
- expected match state: `matched | ambiguous | unmatched`

## GroundTruthHeadingDecision

- raw heading anchor/hash and occurrence
- disposition: excluded region key or expected body decision
- expected `display_level`, role, `include_in_toc`, `starts_page`
- optional display title

## LayoutEvidenceRecord

- page index, bounded text and role
- optional finite bbox
- optional group ID/item index for expanded `list_items`
- provenance: `content-list | native-pdf | ocr`

Records are derived, streamed, capped and never stored in `book.yaml`.

## PrintedContentsAnalysisV2

Private derived artifact with identity `printed-contents-analysis-v2`:

- source/evidence hashes
- candidate and accepted regions with boundary confidence
- logical entries, semantic kinds and per-entry confidence
- best/second-best alignment scores and accepted body IDs
- hierarchy/split proposals and bounded diagnostics

It is revision-pinned, rebuildable and never a public resource.
Its region, canonical, match and hierarchy fields are algorithm output only; the artifact has
no reviewer, confirmation or manual-decision fields.

## LocatableDiagnostic

- stable code, severity, phase and optional confidence
- bounded evidence/proposal summaries
- exactly one primary block, region, page or safe byte-range location
- allowed recovery actions

Recovery does not include supplying region, canonical, body-match or hierarchy decisions.

Complete source text, raw archive paths and OCR output do not cross the management API.

# Mirawind Library 产品规格

- 文档状态：`Draft v0.2`
- 日期：`2026-07-24`
- 当前阶段：Phase 0 完成，进入 M0/M1 技术准备
- 适用范围：产品当前有效决策；历史讨论不构成实现依据
- 规范关键词：
  - `MUST`：必须实现
  - `SHOULD`：应实现，除非有明确理由推迟
  - `MAY`：可选增强
  - `OUT`：明确不在当前范围
  - `OPEN`：尚未冻结

---

## 1. 产品定义

Mirawind Library 是一个单用户、自托管的个人在线图书馆。它将异构电子书，尤其是由 MinerU 生成的 Markdown 图书包，以及后续支持的 EPUB，转换为统一、语义化、可搜索、适合浏览器 AI 理解的网页图书。

产品不是 PDF/EPUB 文件浏览器，也不是博客系统。其核心价值是：

1. 将不同来源的图书统一转换为结构清晰的语义 HTML。
2. 以接近 `zh.d2l.ai` 的方式阅读章节化教材。
3. 提供完整书库管理、全文搜索和私人阅读状态。
4. 对公开图书提供可索引、可分享、可被浏览器 AI 理解的网页。
5. 保留原始文件作为可选附件，而不是将其作为主阅读载体。

## 2. 用户与权限模型

### 2.1 用户角色

系统只有两个访问身份：

- 匿名访客
- 唯一管理员

系统 `MUST NOT` 提供公开注册、多用户空间、社交关注、公开评论或协作编辑。

### 2.2 登录

管理员登录 `MUST` 使用：

- Passkey 作为主要方式
- 备用密码作为恢复方式
- 无注册入口

认证协议实现 `MUST` 复用成熟库，不自行实现 WebAuthn 验证流程。

首次管理员只能通过服务器终端的一次性离线命令创建。正式 Web 服务
`MUST NOT` 暴露注册、邀请或首次初始化入口。首次使用备用密码登录后，
管理员在已有 session 内登记 Passkey。

唯一管理员最多登记 10 个可命名 Passkey。新增、重命名和删除必须具有
有效 session，并且最近一次服务端认证时间不得早于 5 分钟前。删除最后一个
Passkey 时，即使 session 仍处于 5 分钟新鲜期，也必须在该操作中再次验证
备用密码。

备用密码长度 `MUST` 为 16～128 个字符，不强制字符类别组合；系统
`SHOULD` 建议使用密码管理器生成至少 24 个随机字符。密码不得通过命令行
参数、环境变量或日志传递。

Passkey 和备用密码同时失效时，只能通过服务器终端离线完全恢复。恢复
必须设置新密码、撤销全部 session 并删除全部旧 Passkey；系统不提供邮件、
短信或恢复码通道。

### 2.3 图书状态

每本书具有以下状态之一：

- `draft`：草稿，仅管理员可见
- `private`：私人书籍，仅管理员可见
- `public`：公开书籍，匿名访客可读

新导入书籍 `MUST` 默认为 `draft`。

匿名访问 `draft` 或 `private` 的正文、图片、附件和下载地址时，系统 `MUST` 返回 `404`，而不是暴露资源存在。

### 2.4 文件夹可见性

匿名访客只看到至少包含一本公开图书的文件夹分支。只包含草稿或私人图书的文件夹 `MUST` 完全隐藏。

## 3. 信息架构与路由

### 3.1 路由

| 路由                       | 用途                             |
| -------------------------- | -------------------------------- |
| `/`                        | 展示型首页                       |
| `/library`                 | 完整书库根目录                   |
| `/library/[...folderPath]` | 书库中的任意层级文件夹           |
| `/books/:bookKey`          | 路由驱动的书籍详情弹窗           |
| `/read/:bookKey`           | 阅读入口，重定向到实际页面       |
| `/read/:bookKey/:pageKey`  | 实际阅读页面                     |
| `/search`                  | 全站搜索                         |
| `/login`                   | 管理员登录                       |
| `/manage`                  | 导入、任务、错误、存储和系统管理 |

旧的 `/folder/...` 路由已废弃，`MUST NOT` 实现。

### 3.2 图书和页面标识

每本书具有：

- 稳定数字 ID
- 可选全局别名 `alias`

每个页面具有：

- 书内稳定数字 ID
- 可选书内别名 `alias`

别名规则：

- 只允许小写字母、数字和连字符
- 不能是纯数字
- 图书别名全局唯一
- 页面别名在当前图书内唯一

当别名存在时，数字路由 `MUST` 重定向到别名规范地址。

别名修改后：

- 旧别名立即失效
- 不保留历史重定向
- 旧别名立即可复用
- 稳定数字 ID 仍可作为入口，并重定向到当前别名

### 3.3 文件夹路径

文件夹显示名与 URL slug `MUST` 分离。修改显示名不应自动修改 slug。

文件夹移动或 slug 修改后：

- URL 随层级变化
- 旧地址返回 `404`
- 旧路径立即可复用

## 4. 展示型首页

（这块精选书架这里可以先不实现）
首页只承担展示与氛围，不承担完整书库管理。

视觉方向：

- 与 `mirawind.top` 的 Astro Twilight 风格保持一致
- 复用色彩、背景、留白、卡片、圆角、阴影、字体和轻量动效的设计语言
- 不引入博客文章、归档、分类、评论或 RSS

首页 `MUST` 包含：

- 站点名称与简短说明
- 精选书架
- “查看全部书库”入口，指向 `/library`

首页书架支持：

- 手动精选书架
- 自动书架，例如最近加入、最近阅读
- 每个书架可单独隐藏、启用和排序
- 手动书架可配置名称、书籍和顺序

匿名访客只看到公开书籍。管理员登录后可以看到包含私人或草稿书籍的个人自动书架。

私人书架数据 `MUST NOT` 出现在公开 HTML、公共缓存或搜索引擎内容中。

实体书架效果只用于装饰性展示，不得替代 `/library` 的完整管理界面。

## 5. 完整书库

### 5.1 页面模型

`/library` 和 `/library/[...folderPath]` 是同一套界面。根目录只是一个特殊文件夹。

视图参考 KDE Dolphin：

- 文件夹和书籍在同一网格中混排
- 文件夹优先
- 支持图标网格和紧凑列表
- 不使用额外的“文件夹”“书籍”分区标题
- 每个文件夹记忆自身视图与排序设置

### 5.2 排序

每个文件夹支持：

- 标题
- 作者
- 导入时间
- 更新时间
- 手动排序

### 5.3 管理操作

管理员登录后，书库 `MUST` 支持：

- 新建文件夹
- 重命名
- 移动
- 删除
- 拖拽图书进入文件夹
- 拖拽文件夹调整层级
- 多选
- 批量移动
- 批量删除

系统 `OUT`：

- 通用文件复制
- 压缩
- 快捷方式
- 任意服务器文件操作
- 把逻辑文件夹映射为服务器物理路径

### 5.4 图书卡片

图书卡片只显示：

- 封面
- 标题
- 可选作者或整理者
- 管理员登录时的轻量状态标记

卡片 `MUST NOT` 显示：

- 阅读进度
- ISBN
- 文件格式
- 标签
- 描述
- 大量元数据

交互：

- 点击封面：直接进入阅读
- 点击书名或菜单：打开详情弹窗

## 6. 书籍详情弹窗

`/books/:bookKey` 是路由驱动的详情弹窗，不是独立页面模型。

行为：

- 从书库打开时，背景保留当前文件夹和滚动位置
- 关闭后恢复原位置
- 直接访问该路由时，先呈现书库背景，再打开弹窗
- 移动端使用全屏覆盖

内容包括：

- 封面
- 标题、作者等元数据
- 简介
- 目录预览
- 开始阅读
- 可用原文件下载
- 管理员管理操作

当保存多个原文件时，下载菜单显示格式与文件大小。

M1 不设置独立的原文件下载开关。图书为 `public` 时，其登记为原文件的
MinerU ZIP、PDF、EPUB 等文件允许匿名下载；图书为 `draft` 或 `private`
时仅管理员可以下载。`book.yaml`、`document-manifest.json`、搜索索引、
私人笔记、批注和其他内部文件 `MUST NOT` 作为原文件下载。

下载响应 `MUST`：

- 使用 `Content-Disposition: attachment`
- 提供安全的 UTF-8 文件名和 ASCII 回退名
- 返回正确的类型、长度、`nosniff`、强 ETag 和 Range 支持
- 每次完整请求和 Range 请求都重新检查当前权限
- 返回 `Cache-Control: private, no-store`
- 通过 `X-Robots-Tag` 禁止索引、存档和摘要

## 7. 阅读器

### 7.1 页面结构

桌面端：

- 固定顶部阅读栏
- 左侧全书目录
- 中间正文
- 右侧当前页面提纲
- 私人笔记与批注使用按需打开的右侧抽屉

顶部栏 `SHOULD` 参考 D2L 的轻量风格，包含：

- 返回书库
- 书名或当前章节
- 搜索
- 书签
- 笔记
- 阅读设置

顶部栏 `MUST` 固定显示，不自动隐藏。

移动端默认只显示正文，目录、笔记和设置通过抽屉打开。

### 7.2 阅读导航

支持：

- 左侧目录
- 页面底部上一页、下一页
- 桌面键盘左右方向键

当焦点位于输入框、Vditor、代码交互区域时，方向键不得触发翻页。

移动端 `MUST NOT` 依赖左右滑动翻页。

正常翻页进入页面顶部；从搜索结果、书签、内部锚点进入时，跳转到目标位置。

### 7.3 阅读入口

`/read/:bookKey`：

- 管理员以前读过：跳转最后页面并恢复页内位置
- 管理员首次阅读：跳转第一内容页
- 匿名访客：跳转第一内容页

实际正文始终位于 `/read/:bookKey/:pageKey`。

详情弹窗应提供“从头开始”入口。

### 7.4 阅读设置

管理员可以设置：

- 字号
- 行高
- 正文宽度
- 浅色/深色
- 中文字体
- 拉丁字体
- 等宽字体

设置以全局为主，单书可覆盖，并跨设备同步。

匿名访客使用站点默认设置。是否提供匿名本地临时设置仍为 `OPEN`。

### 7.5 图片

- 保留 MinerU 原始图片质量
- 默认适配正文宽度
- 不超过原图尺寸放大
- 点击打开灯箱
- 支持缩放和平移
- 超宽图片允许横向滚动
- 移动端适配屏幕宽度
- 图名显示在图下方

### 7.6 表格

- 使用语义化 HTML 表格
- 表名显示在表格上方
- 保留原编号
- 超宽表格允许横向滚动

### 7.7 公式

- 使用 KaTeX
- 优先在发布时预渲染
- 保留原始 LaTeX
- 保留原书已有公式编号和正文引用
- 不给未编号公式自动编号
- 不统一重编号

KaTeX 渲染失败时：

- 导入预览显示诊断
- 不强制阻止发布
- 网页显示原始 LaTeX，并标记渲染失败

### 7.8 代码

- 使用语法高亮
- 支持复制
- 横向滚动
- 默认不显示行号
- 每本书可覆盖行号设置
- 保留源文件名或标题
- 未知语言按纯文本处理
- 不提供在线执行

### 7.9 脚注

- 正文使用上标编号
- 悬停或点击显示浮层
- 页面末尾保留完整脚注列表
- 正文与脚注双向链接
- 保留原编号

## 8. 输入与导入

### 8.1 MinerU

扫描 PDF、图片 PDF 和复杂 PDF 由外部 GPU 机器运行 MinerU。服务器 `MUST NOT` 在 MVP 中运行 MinerU 或 GPU 任务。

每次导入只接受一个完整 MinerU 输出 ZIP，且该 ZIP 只对应一本书。

系统递归发现 Markdown，并结合 MinerU Cloud `full.md`、MinerU CLI
`<stem>.md`、相邻伴随文件和资源引用完整性识别主正文：

- 只有一个无错误的高置信候选时自动选择
- 普通单 Markdown 必须由管理员确认
- 多个书籍 bundle 必须拒绝，并要求拆包后重新上传
- 主 Markdown 所在目录是其相对资源引用基准
- 没有可用主 Markdown 时导入失败并显示候选诊断

导入流程：

1. 上传
2. 安全解包
3. 解析和校验
4. 显示诊断
5. 人工确认目录与配置
6. 生成草稿预览
7. 发布

M1 不按固定时长自动删除待确认或已完成的导入记录及其仍被引用的上传文件。
失败的未完成写入与 staging 仍立即清理；未来若增加导入历史保留期，必须提供
独立的状态、引用和恢复规则。

M1 从 `draft` 切换为 `public` 时不要求管理员执行公开权利确认，也不以
权利声明阻断发布。发布应用层必须保留统一的发布前策略检查接口，M1 默认
策略允许发布；系统不得伪造一条管理员没有作出的确认记录。

校验至少包括：

- 主 Markdown
- 引用图片
- 数学公式
- 元数据
- 目录候选
- 缺失资源
- 可疑或危险文件

M1 强制执行以下资源限制：

| 限制               |                数值 |
| ------------------ | ------------------: |
| 上传 ZIP           |               2 GiB |
| 实际解压总量       |               8 GiB |
| 文件与目录条目总数 |              20,000 |
| 单个解压文件       |               2 GiB |
| 候选主 Markdown    |             256 MiB |
| 单张图片           |    100,000,000 像素 |
| 图片任一边         |         32,768 像素 |
| 目录深度           |               20 层 |
| 单个路径组件       |   255 个 UTF-8 字节 |
| 完整相对路径       | 2,048 个 UTF-8 字节 |
| 后台导入或重建     |             30 分钟 |

当对应未压缩数据超过 64 MiB 时，单条目和整包的解压倍率均不得高于
200:1。所有体积与倍率限制必须按实际读取、解码或写出的数据再次验证，
不得只信任 ZIP 元数据。任一安全限制失败时整次导入失败并清理暂存目录。

### 8.2 EPUB

EPUB 直接上传，由系统解析，不经过 MinerU。

EPUB 支持不进入首个垂直切片。最终实现 `MUST` 将 EPUB 转为内部标准文档树和普通语义 HTML，不使用 iframe 作为最终正文载体。

具体解析库仍为 `OPEN`。

### 8.3 原始文件

M1 将上传的 MinerU ZIP 登记为该版本的可下载原文件。后续支持的原 PDF、
图片包和 EPUB 可以使用相同模型登记。

原文件：

- 不作为主正文
- 不参与服务器端 MinerU 处理
- 可单独删除，而不影响网页版图书
- 下载权限直接跟随图书状态，不使用独立下载开关

### 8.4 MinerU 包清理

MinerU ZIP 是导入包，不是网页运行格式。上传的原 ZIP 作为登记原文件保留
以供下载；网页正文不在请求时从 ZIP 解压或解析。

系统永久保存：

- 主 Markdown
- 正文实际引用的图片
- 目录与必要元数据
- 生成配置
- 上传的原始 MinerU ZIP
- 其他已登记原始文件

系统应丢弃：

- `layout.pdf`
- `span.pdf`
- `middle.json`
- `model.json`
- 未引用临时资源
- 调试中间产物

## 9. 更新、重新导入与事务

更新一本书时：

- 必须明确选择目标图书，或包内携带稳定 `book_id`
- 标题、ISBN、文件名只能提示疑似重复，不能自动合并
- 新正文和图片替换旧版本
- 图书稳定 ID、文件夹、元数据、路由别名和人工配置默认保留
- 服务器现有配置默认优先
- 冲突必须显示并由管理员选择
- 不允许静默覆盖

每本书使用同一文件系统内的 staging 目录与按 `version_id` 命名的不可变
版本目录。SQLite 的 `current_version_id` 是当前发布版本的唯一权威指针；
文件系统 `MUST NOT` 维护第二个 `current` 指针或可变当前目录。

重新导入必须使用文件先固化、数据库后切换的两阶段协议：

1. 在 staging 中构建并校验完整新版本。
2. 持久化全部文件后，原子重命名为不可变版本目录。
3. 在 SQLite 事务中写入 `ready` 版本及其带版本 ID 的 FTS5 索引。
4. FTS5 完整写入并校验成功后，通过短事务比较旧版本和配置修订号。
5. 原子更新 `current_version_id` 和新旧版本状态。

任何构建、FTS5、版本比较或数据库提交失败都必须继续服务完整旧版本。
`ready` 或孤立版本不得自动公开。启动恢复必须识别 staging、孤立目录、
缺失文件和损坏当前版本；当前版本损坏时回退到最近一个校验通过的已发布
版本，无可回退版本时只让该书返回 `503`。

发布事务不得删除旧版本。M1 至少保留当前版本和上一个成功发布版本；更早
版本等待至少 24 小时后由独立回收任务连同其 FTS5 数据清理。

## 10. Markdown、文档树与发布模型

### 10.1 唯一可编辑正文

Markdown 是正文唯一可编辑源文件。

系统不维护第二份可人工编辑的结构化正文。

### 10.2 标准化文档树

导入时：

- 使用成熟 Markdown AST 生态解析
- 生成标准化文档树
- 为可批注内容生成稳定块 ID
- 目录、拆页、搜索、高亮和最终 HTML 都基于该文档树

完整 AST 只在后台编译期间存在，不长期持久化。Markdown 和版本化
`book.yaml` 是权威源；每个发布版本持久化独立版本号的
`document-manifest.json`、预生成 HTML、资源映射和搜索索引。

稳定 ID 分配给标题、段落、列表项、引用、代码块、公式、图片、表格、脚注
和教材语义容器，不分配给行内格式。ID 首次导入时随机生成，重新导入时只有
可靠匹配才能继承；旧 ID 不复用。

manifest 为每个块保存当前 Markdown 的相对路径、起止行列、规范化可见文本
指纹和资源映射。源位置不参与身份判断。`book.yaml` 与 manifest 使用独立
整数 `schema_version`，未知的更新版本必须拒绝而不能猜测解释。

M1 的可见文本规范化使用渲染后文本、Unicode NFC 和统一换行；精确高亮
偏移规则推迟到 M3。

### 10.3 语义 HTML

正文 `MUST` 是完整语义 DOM：

- `h1`–`h4`
- 段落
- 列表
- 引用
- 表格
- 脚注
- 代码
- 公式
- 图片与题注
- 特殊教材块

正文 `MUST NOT` 使用以下形式作为主内容：

- PDF.js
- Canvas
- 页面截图
- iframe
- 仅客户端 JavaScript 生成正文
- 视口虚拟化导致当前页面正文不在 DOM 中

### 10.4 发布

公开正文由单书编译器增量生成：

- HTML
- 页面 manifest
- 全书目录
- 页面提纲
- KaTeX 结果
- 代码高亮结果
- 搜索索引数据
- 资源映射
- 构建诊断

系统 `MUST NOT` 每导入一本书就执行整站 Astro rebuild。

所有生成产物保存在非公开数据目录。Astro 根据状态与权限读取并返回。

上传、重新导入和出版配置变化只触发后台单书重建。阅读请求只读取已发布的
预生成版本，`MUST NOT` 在请求路径中解析 Markdown、构建 AST、运行 KaTeX、
执行代码高亮或生成搜索索引。重建期间继续服务旧版本，成功后原子切换。

公开书籍：

- 允许公共缓存
- 允许搜索引擎索引

私人和草稿书籍：

- 必须鉴权
- 禁止公共缓存
- 禁止搜索引擎索引

## 11. 目录、拆页与链接

### 11.1 目录生成

来源优先级：

1. EPUB nav 或可靠书签
2. Markdown 标题
3. 标题样式和正则候选
4. 未来可选 LLM 辅助

管理员在导入预览中可以：

- 选择目录标题
- 重命名
- 调整层级
- 确认拆页
- 为顶层内容指定 `frontmatter`、`body`、`appendix` 或 `backmatter`

M1 不允许在目录界面拖拽改变正文顺序；需要重排时修改 Markdown 后重新
导入。页面 alias 字段从第一版起保留在配置中，但 M1 不提供编辑入口。

目录勾选只决定标题是否出现在导航中，不得删除或隐藏对应正文。重命名使用
`display_title`，层级调整使用 `display_level`，拆页使用标题节点上的
`starts_page`；这些覆盖值写入 `book.yaml`，不得改写原 Markdown。

配置后的层级决定目录、页面提纲、编号和最终 `h1`–`h4`，并且必须连续有效。
M1 只允许在标题节点前拆页，不允许在段落、公式、表格或图片中间拆页。

管理界面负责原子更新 `book.yaml`，管理员无需手工编辑 YAML。

### 11.2 标题编号

默认规范化：

- 一级：章节编号
- 二级：`1.1`
- 三级：`1.1.1`
- 四级及以下：不自动编号

前言、序言、导论、符号表等前置内容不编号。

后记、参考文献、索引、致谢等后置内容不编号。

附录优先保留原编号；无法判断时使用 Appendix A、B 等。

每本书可以选择保留原编号。

### 11.3 拆页

默认：

- 存在二级标题时，每节一页
- 没有二级标题，或章节较短时，整章一页
- 中文约 4000 字符、英文约 2500 词作为初始短章节参考阈值
- 图片和公式密集时降低阈值
- 每本书可人工覆盖

### 11.4 内部链接

系统必须保留和修复：

- 标题链接
- 图表引用
- 公式引用
- 脚注
- 跨页面链接

系统不得把普通文本引用凭猜测自动转成链接。

## 12. 教材特殊内容块

支持以下 Markdown 容器：

- `definition`
- `theorem`
- `proof`
- `example`
- `exercise`
- `solution`
- `note`
- `warning`

未识别或未标记内容按普通正文显示。

系统不要求 MinerU 自动识别所有特殊块；管理员可以在 Markdown 中手动补充。

## 13. 元数据与封面

### 13.1 元数据

唯一必填字段：

- 标题

可选：

- 封面
- 作者或整理者
- 简介
- 语言
- 出版社
- 年份
- 版次
- ISBN-10
- ISBN-13

空字段不显示，也不强制填写。

自动字段：

- 文件夹
- 状态
- 文件格式
- 文件大小
- 导入时间
- 更新时间
- 稳定 ID

### 13.2 自动封面

没有封面时，系统生成稳定的文字封面：

- 纯色
- 渐变
- 纸张纹理
- 几何模板

可调整：

- 主色
- 字体
- 标题
- 副标题
- 作者或整理者

生成结果基于图书 ID 保持稳定，可被自定义封面替换。

系统不提供自由拖拽的复杂封面设计器。

## 14. 搜索

第一版使用 SQLite FTS5，不部署独立搜索服务。

索引范围：

- 书名
- 作者
- 章节标题
- 正文块
- 私人笔记和批注的独立索引范围

匿名访客只搜索公开正文。

管理员默认搜索所有可见正文，并可切换到“笔记与批注”。

搜索结果标记来源：

- 正文
- 笔记
- 批注

结果应定位到：

- `book_id`
- `page_id`
- `block_id`

正文主索引使用 FTS5 trigram 和 `detail=full`。3 个及以上 Unicode 字符
搜索书名、作者、章节标题和正文；1～2 个字符只对书名、作者和章节标题执行
受限 `LIKE` 或 `instr()` 回退，不扫描完整正文。界面必须明确提示短查询
范围。

查询使用与索引一致的 NFC 和换行规范化，并编码为安全的 FTS5 字面短语。
M1 不使用 `unicode61` 作为中文正文主索引，不引入中文分词扩展或全正文
短词表。所有查询继续同时过滤权限和 `current_version_id`。

## 15. 高亮、批注、书签与进度

这些数据全部私人、登录后可见，不能进入公开 HTML。

### 15.1 高亮

普通文字高亮采用复合锚点：

- `book_id`
- `page_id`
- `block_id`
- 块内起止偏移
- `exact`
- `prefix`
- `suffix`
- 源版本
- 块指纹

高亮不允许跨正文块。

公式、表格和图片只支持整体批注，不进行局部范围高亮。

颜色：

- 默认黄色
- 可选蓝色、红色、绿色
- 不支持任意颜色

每条高亮可附带评论。

选区工具条包括：

- 一键黄色高亮
- 添加评论
- 插入 `notes.md`
- 复制
- 其他颜色子菜单

### 15.2 重新导入后的迁移

重新导入时：

- 可靠匹配的块继承旧 ID
- 新块生成新 ID
- 删除或无法确定的批注进入“待重新定位”
- 不自动删除
- 不进行宽松的整书 LLM 猜测

### 15.3 进度和书签

管理员跨设备同步：

- 当前图书
- 当前页面
- 页内位置
- 手动书签

恢复优先使用段落锚点，失败时使用滚动百分比回退。

书库卡片不显示阅读进度。

## 16. `notes.md`

每本书第一版固定一个 `notes.md`。

编辑器使用 Vditor：

- 默认 IR 即时渲染模式
- 支持 SV 分屏源码模式
- 只保存原始 Markdown
- KaTeX
- 自动保存
- 简单历史

只读展示使用站点统一渲染管线，不使用 Vditor 作为正文渲染器。

历史规则：

- 最近 30 个快照
- 至少保留 30 天
- 内容变化时最多每 10 分钟生成一个快照
- 恢复历史前生成保护快照

不实现 Git 分支、复杂 diff 或多人协作。

## 17. 导出

每本书可导出 ZIP，包含：

- `book.yaml`
- 清理后的 Markdown
- 正文引用资源
- 可选原始文件
- 可选私人数据

默认不导出：

- 笔记
- 高亮
- 批注
- 书签
- 进度

导入私人数据到已有图书时：

- 默认保留现有数据
- 可选择整体替换
- 不做自动智能合并

`book.yaml` 只保存可移植出版配置，不保存私人数据。

## 18. 存储、部署与回收站

### 18.1 部署

- 单台 Linux 服务器
- Docker Compose
- Astro Node Web 进程
- 同代码库独立 worker 进程
- React Islands
- SQLite + WAL
- SQLite 持久化任务队列
- 本地文件系统
- Caddy 或等价反向代理
- HTTPS
- 单 Web 实例和单 worker 实例

M1 全局同时只运行一个导入或重建任务。worker 使用租约心跳领取任务，每个
任务在可终止子进程中执行；进程或服务器中断造成的任务最多自动重试一次，
资源超限、内容错误或第二次中断不得自动重试。已构建为 `ready` 的版本不得
因恢复流程自动公开。任务取消或达到 30 分钟上限时先请求协作式终止；10 秒
内未退出则强制终止整个任务进程组，确认关闭后才能写入最终任务状态。

不使用：

- 微服务
- PostgreSQL/MySQL
- Redis
- 对象存储
- 分布式任务系统
- 多服务器共享 SQLite

### 18.2 存储统计

管理页显示：

- 磁盘总量、已用、剩余
- 每本书占用
- 网页正文与图片
- 原始附件
- 笔记与历史

原始附件可独立删除，网页版继续保留。

### 18.3 回收站

删除图书后：

- 立即从书库、搜索和公开访问中隐藏
- 全部数据保留 30 天
- 支持恢复
- 支持永久删除
- 到期自动清理

### 18.4 数据持久性

备份不作为产品 UI 功能。

但应用升级和卸载 `MUST NOT` 默认删除宿主持久化数据。迁移到新机器时，应支持复制持久化数据目录并运行一致性检查。

## 20. SEO 与缓存

公开内容默认可被搜索引擎索引：

- `/`
- 公开 `/library/...`
- 公开 `/books/:bookKey`
- 公开 `/read/:bookKey/:pageKey`

不索引：

- `/search`
- `/login`
- `/manage`
- 私人或草稿图书
- 私人笔记、批注、书签、进度
- PDF、EPUB、MinerU ZIP 等原文件下载响应

规范地址优先使用当前 alias。

缓存规则：

- 公开 HTML：`public, max-age=0, must-revalidate`，使用包含当前版本、
  请求路由和渲染器版本的强 ETag
- 公开书籍的版本化图片等阅读资源：
  `private, max-age=31536000, immutable`
- PDF、EPUB、MinerU ZIP 原文件下载：`private, no-store`
- `draft`、`private`、登录、管理页面和私人 API：`private, no-store`
- alias 跳转、不存在路径和隐藏私人资源的 `404`：`no-store`
- 带内容哈希且不含书籍数据的站点 JS、CSS 和字体：公共长期 immutable

公开可缓存 HTML `MUST NOT` 包含管理员身份或私人状态。书籍改为私人后，
服务器必须立即拒绝新的匿名访问；已经在公开期间交付给客户端的副本无法
收回。

## 23. 产品级完成原则

任一功能只有满足以下条件才算完成：

1. 用户可观察行为符合已批准规格。
2. 权限规则覆盖 HTML、图片、附件和 API。
3. 失败路径有明确行为。
4. 数据变更不会暴露半完成状态。
5. 自动测试覆盖核心成功和失败场景。
6. 生成产物可由源数据重建。
7. 文档、代码和当前规格保持一致。
8. 实质性复用或改写的外部代码具有可审计来源和兼容许可证，提交历史通过约定式提交门禁。

公开阅读页在单机、未命中公共缓存时，服务端响应时间 p95 `MUST` 不超过
300 ms。M1 必须使用代表性大型 MinerU ZIP 建立上传、导入、重建和阅读
响应基准；后台重建耗时不得转化为读者打开页面的等待时间。

真实兼容性与最终性能验收使用测试阶段由用户提供的 2～3 本、每本约数百页
且由 MinerU `3.4.4` 生成的输出 ZIP。M1 的正式兼容性声明以该版本为边界。
真实样本保存在服务器仓库外的受控目录，或本机工作树内被 Git 整目录忽略的
`tests/fixtures/mineru/real/`。已跟踪文件只登记不含书名或正文的样本格式与
使用说明；本机清单使用代号、MinerU 版本、页数范围、大小和 SHA-256。普通
CI 可在样本不存在时明确跳过真实样本测试，但 M1 最终验收不得用小型或合成
fixture 代替。
